= Known limitations in NetApp Ransomware Resilience
:hardbreaks:
:icons: font
:imagesdir: ./media/

[.lead]
Known limitations identify the platforms, devices, and functions that NetApp Ransomware Resilience doesn't support or that don't interoperate correctly with it. Review the limitations that apply to your environment.

== Readiness drill reset option issue

If you select an ONTAP 9.11.1 volume for the ransomware attack readiness drill, Ransomware Resilience sends an alert. If you recover the data using the "clone-to-volume" option and reset the drill, the reset operation fails.

== Amazon FSx for NetApp ONTAP limitations

The following limitations apply to Amazon FSx for ONTAP:

* Backup policies aren't supported for Amazon FSx for ONTAP. In this environment, use Amazon FSx backups to perform backup operations. You can restore these workloads using Ransomware Resilience. 
* Restore operations are performed from snapshots only.

== Azure NetApp Files limitations

The following limitations apply to Azure NetApp Files:

* Ransomware protection strategies with backup policies aren't supported for Azure NetApp Files. Instead, you can use Azure NetApp Files backup.
* Ransomware protection strategies with replication aren't supported for Azure NetApp Files. 
* Azure NetApp Files doesn't support FPolicy or user behavior detection. Azure NetApp Files also doesn't support entropy forensics. 
* When selecting a protection strategy, ensure that its snapshot schedule is compatible with Azure NetApp Files. The most frequent snapshot schedule available in Azure NetApp Files is hourly. 
* Avoid using link:reference-soar.html[SOAR playbooks] with Azure NetApp Files because Azure NetApp Files APIs block automated actions. 
* Some event data is not included in link:task-siem.html[SIEM reports] for Azure NetApp Files configurations. 
* File-level restore is not available when you link:task-custom-restore.html[restore a workload] for Azure NetApp Files. 

== Google Cloud NetApp Volumes limitations

The following limitations apply to Google Cloud NetApp Volumes:

* Currently, you can only apply encryption- and FPolicy-based protection strategies to Google Cloud NetApp Volumes workloads. You can't apply user behavior protection strategies.
* Protection strategies with replication aren't currently supported for Google Cloud NetApp Volumes.

== SAN storage limitations 

The following limitations apply to SAN (block storage) workloads:

* When Ransomware Resilience generates warnings for SAN workloads, those warnings are based only on high entropy. 
* SAN workloads can only be restored using a link:task-custom-restore.html[custom restore]. Clean restore isn't currently available for SAN workloads.  

== Multi-admin verification

Multi-admin verification is not supported in Ransomware Resilience or the NetApp Console. If you've configured link:https://docs.netapp.com/us-en/ontap/multi-admin-verify/[multi-admin verification in ONTAP^], you won't be able to enable protection, conduct a readiness drill, or perform any restore operations. Disable multi-admin verification before you attempt any of these operations.
